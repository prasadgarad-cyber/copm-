# Website Design System

## Design Reference

Use [SCFO / Scale & Form](https://scfo.de/) as a **visual direction reference**, not as a site to copy.

The target is the same kind of **editorial, typography-led, structured, premium layout language**, but with **no animation or motion effects**.

SCFO's structure is useful as inspiration because it combines strong typography, numbered sections, generous spacing, clear hierarchy, measurable content, process-oriented sections, and real product/work demonstrations.

## Primary Goal

The website should feel:

- Editorial
- Premium
- Confident
- Minimal but not empty
- Typography-driven
- Structured
- Product-specific
- Intentional
- Modern without looking like a generic AI/SaaS template

It should **not** feel like a typical AI-generated landing page.

---

# DO NOT USE

## 1. Harsh Gradients

Do not use:

- Large neon gradients
- Aggressive purple-blue gradients
- Rainbow gradients
- Glowing gradient blobs
- Gradient text as decoration
- Gradient backgrounds used only to make the page look "modern"

If gradients are genuinely necessary for the product, keep them subtle and purposeful.

## 2. Pure White Backgrounds

Do not default to `#FFFFFF` as the entire website background.

Prefer an intentional neutral system such as:

- Warm off-white
- Soft grey
- Charcoal
- Deep neutral
- Muted product-specific tones

The background should support the typography and content rather than looking like an empty template.

## 3. Rainbow Coloring

Do not use multiple unrelated accent colors.

Avoid:

- Rainbow icons
- Multi-colored feature cards
- Random colored sections
- Every button having a different color
- AI-dashboard-style rainbow decoration

Use a restrained palette with a strong primary accent and supporting neutrals.

## 4. Three Feature Cards in a Row

Do not automatically create:

`Feature 1 | Feature 2 | Feature 3`

This is one of the most common generic SaaS layouts.

Instead, choose layouts based on the information:

- Large editorial blocks
- Numbered sections
- Split layouts
- Horizontal lists
- Feature + visual
- Product workflow
- Comparison layouts
- Data-driven sections
- Full-width statements
- Asymmetric compositions

If cards are necessary, their number and layout should come from the content rather than a fixed template.

## 5. Liquid Glass / Excessive Glassmorphism

Do not use:

- Frosted glass cards everywhere
- Blurred translucent panels
- Excessive backdrop blur
- Floating glass navigation
- Glassmorphism as the primary visual identity

Use solid surfaces, borders, spacing, typography, and contrast to create hierarchy.

## 6. Em Dashes

Do not use the em dash character:

`—`

Use commas, periods, colons, parentheses, or separate sentences instead.

This applies to:

- Headings
- Body copy
- Buttons
- Labels
- Navigation
- Marketing copy
- UI text

## 7. Fake Testimonials

Never invent testimonials.

Do not create:

- Fake customer names
- Fake companies
- Fake quotes
- Fake profile photos
- Fake ratings

If genuine testimonials are unavailable, remove the testimonial section.

Use real evidence instead:

- Real users
- Real case studies
- Real metrics
- Real project results
- Real product demonstrations
- Verified feedback

## 8. Three Pricing Tiers

Do not automatically create:

`Basic | Pro | Enterprise`

Only show pricing if the actual product has multiple plans.

If pricing is required, use the real business model.

Possible alternatives:

- Single plan
- Usage-based pricing
- Custom quote
- Calculator-based pricing
- Feature-based pricing
- Clearly differentiated plans

Never invent prices or features.

## 9. No Real Product Demo

A website must show the actual product whenever possible.

Do not rely entirely on:

- Marketing slogans
- Abstract illustrations
- Decorative dashboards
- Fake UI screenshots
- Generic mockups

Prefer:

- Real screenshots
- Real application UI
- Interactive product preview
- Live demo
- Actual workflow
- Before/after examples
- Real output
- Real data visualization

The user should understand **what the product does by seeing it**, not only by reading about it.

## 10. Sparkle Icons

Do not use sparkle icons such as:

`✨`

Do not use decorative sparkles to make the product appear AI-powered or futuristic.

Icons should communicate meaning.

Prefer:

- Functional icons
- Simple geometric marks
- Product-specific symbols
- Data visualizations
- Diagrams
- Real interface elements

## 11. Basic Pastel Colours

Do not use a generic pastel SaaS palette.

Avoid:

- Baby blue
- Pale pink
- Lavender
- Mint
- Peach
- Soft yellow

used together simply because they look pleasant.

The palette should feel intentional and brand-specific.

# TYPOGRAPHY DIRECTION

Typography is one of the **most important parts of the design**.

Use typography as a visual system, not just as readable text.

## Headlines

Headlines should be:

- Large
- Strong
- Editorial
- Confident
- Carefully spaced
- Visually dominant

Avoid overly rounded, bubbly, or generic startup typography.

Use large display typography when appropriate, but maintain hierarchy and readability.

## Section Labels

Use small, precise labels such as:

`01 / OVERVIEW`

`02 / PRODUCT`

`03 / WORKFLOW`

`04 / RESULTS`

This numbered editorial approach can be used to create structure and rhythm.

## Body Text

Body text should be:

- Clean
- Readable
- Controlled in width
- Concise
- Clearly subordinate to headings

Do not fill the page with oversized paragraphs.

## Typography Hierarchy

Create a clear relationship between:

1. Eyebrow / section number
2. Main heading
3. Supporting statement
4. Body copy
5. Metadata
6. CTA

Typography should create most of the visual hierarchy before decorative elements are introduced.

---

# LAYOUT DIRECTION

Use the **editorial structure and spacing philosophy** of SCFO as inspiration.

Reference characteristics include:

- Strong vertical rhythm
- Large section headings
- Numbered sections
- Generous whitespace
- Full-width compositions
- Clear content hierarchy
- Strong left alignment
- Carefully controlled content widths
- Alternating section compositions
- Information presented as a system
- Real project/work sections
- Process sections
- Data and metrics
- Clear final CTA

Do not copy SCFO's exact content, branding, assets, or implementation.

The goal is to reproduce the **design principles**, not the website.

---

# SECTION STRUCTURE

Do not use the generic:

`Hero → 3 Features → Testimonials → Pricing → CTA`

Instead, choose a structure appropriate to the product.

A possible structure is:

### 01 / INTRODUCTION

Large typography-led statement.

Clearly explain what the product is.

### 02 / PRODUCT

Show the real product.

Use a large product screenshot, interactive preview, dashboard, workflow, or real output.

### 03 / CAPABILITIES

Explain what the product actually does.

Use editorial rows or structured sections instead of three equal cards.

### 04 / RESULTS

Show real measurable outcomes where available.

Examples:

- Performance
- Usage
- Time saved
- Accuracy
- Projects completed
- Adoption

Never invent metrics.

### 05 / WORKFLOW

Show how the product works.

Use numbered steps or a visual process.

### 06 / PROOF

Use real case studies, real projects, real users, or real evidence.

Do not fabricate social proof.

### 07 / DETAILS

Answer important questions, explain technical details, or show the system behind the product.

### 08 / CTA

End with a strong, simple action.

Do not create a generic giant gradient CTA.

---

# SPACING

Use whitespace deliberately.

Prefer:

- Large section spacing
- Clear vertical rhythm
- Comfortable text margins
- Strong separation between sections
- Controlled content widths

Avoid:

- Every section looking like a separate card
- Excessive padding inside tiny cards
- Dense dashboard-like layouts when unnecessary
- Huge empty areas with no purpose

Whitespace should create hierarchy, not emptiness.

---

# BORDERS AND SURFACES

Prefer subtle structure through:

- Thin borders
- Dividers
- Solid surfaces
- Background changes
- Typography
- Spacing

Do not depend on:

- Huge shadows
- Glass effects
- Glow effects
- Excessive rounded corners

Border radius should be restrained and consistent.

---

# ANIMATION

## IMPORTANT: NO ANIMATION

The website should be **static**.

Do not use:

- Scroll-triggered animations
- Parallax
- Text reveal animations
- Marquee animations
- Floating objects
- 3D motion
- Cursor-following effects
- Animated gradients
- Glowing pulses
- Page transition animations
- Animated counters
- Magnetic buttons
- Hover transformations that significantly move elements

Simple functional interaction is acceptable, such as:

- Button hover state
- Link hover state
- Focus state
- Accordion open/close
- Dropdown interaction
- Tabs
- Form validation

These should be immediate and functional rather than decorative motion.

---

# INTERACTION

Interaction should communicate functionality.

Prefer:

- Clear hover states
- Clear active states
- Accessible focus states
- Functional tabs
- Useful filters
- Expandable information
- Product controls

Avoid interaction that exists only to impress the visitor.

---

# ICONOGRAPHY

Use icons only when they improve comprehension.

Preferred:

- Simple line icons
- Product-specific icons
- Technical symbols
- Data visualization
- Geometric marks

Avoid decorative icon collections.

---

# COPY STYLE

Copy should be direct and specific.

Avoid generic AI/SaaS phrases such as:

- "Revolutionize your workflow"
- "Unlock your potential"
- "The future of everything"
- "Supercharge your productivity"
- "Built for the future"

unless the phrase is genuinely relevant and specific.

Prefer:

- What the product does
- Who it is for
- What problem it solves
- How it works
- What users get
- Evidence of the result

Do not use em dashes.

---

# RESPONSIVE DESIGN

The editorial layout must remain strong on mobile.

Do not simply shrink the desktop layout.

On mobile:

- Preserve typography hierarchy
- Maintain meaningful spacing
- Stack content logically
- Keep important product visuals visible
- Avoid horizontal overflow
- Maintain readable line lengths
- Keep section numbering and structure
- Remove unnecessary decorative elements

---

# ACCESSIBILITY

Maintain:

- Strong text contrast
- Keyboard navigation
- Visible focus states
- Semantic HTML
- Descriptive labels
- Accessible form controls
- Proper heading hierarchy

Do not sacrifice usability for visual style.

---

# FINAL DESIGN TEST

Before considering the website finished, ask:

- Does it look like a specific product rather than an AI template?
- Is typography doing most of the visual work?
- Is the layout editorial and structured?
- Is the actual product visible?
- Are there real demonstrations or real evidence?
- Is the color palette restrained?
- Are there no harsh gradients?
- Is the background intentionally chosen rather than pure white?
- Are there no rainbow colors?
- Are there no default three-card feature rows?
- Is there no liquid glass aesthetic?
- Are there no fake testimonials?
- Is there no automatic three-tier pricing?
- Are there no sparkle icons?
- Are there no em dashes?
- Is there no decorative animation?
- Does the website still look premium without motion?

## Core Principle

**Typography + layout + real product evidence should create the visual identity.**

Do not use gradients, glassmorphism, fake social proof, decorative icons, excessive cards, or animation as shortcuts for good design.

The final website should feel **editorial, premium, restrained, highly intentional, and specific to the product**, with SCFO-style typography and layout principles but without copying the site and without animation.
